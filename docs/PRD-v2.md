## 二、功能 PRD

### A. 优化策略按钮

#### 目标
当用户在 Dashboard 或 ProjectRoom 中点击"优化策略"时，提供一个**智能诊断与优化建议**的交互体验。

#### 交互流程
```
用户点击"优化策略"
    ↓
显示加载状态 + "正在分析..."
    ↓
调用 API 获取当前上下文数据
    ↓
展示"优化建议卡片"：
┌─────────────────────────────────┐
│ 📊 优化策略建议                    │
├─────────────────────────────────┤
│ [Agent负载分析]                   │
│ • 平头舅舅 负载 92% - 建议分流     │
│ • 平头叔 负载 45% - 正常          │
│                                 │
│ [项目阻塞分析]                    │
│ • 项目A - 等待平头叔 PRD          │
│ • 项目B - 等待平头姑 测试完成      │
│                                 │
│ [建议操作]                        │
│ ○ 分流任务到空闲Agent              │
│ ○ 调整项目优先级                   │
│ ○ 提醒阻塞节点负责人               │
└─────────────────────────────────┘
    ↓
用户选择建议 → 执行对应操作
用户关闭 → 返回
```

#### 数据来源
- Agent 负载 → `/api/openclaw/agents`
- 项目阻塞 → `/api/openclaw/projects` 或 `/api/openclaw/workspace`
- 建议生成 → 前端基于规则计算（无需 LLM）

#### 边界条件
- API 失败 → 显示"数据加载失败，请重试"
- 无阻塞项目 → 显示"所有项目正常"
- Agent 全部空闲 → 显示"负载均衡，无需调整"

### B. Agent Commander 确认卡片

#### 目标
用户发送指令给 Agent 前，增加**AI理解确认**步骤，防止误解需求。

#### 交互流程
```
用户输入指令并点击"发送"
    ↓
显示"AI 正在理解指令..."
    ↓
展示"理解确认卡"：
┌─────────────────────────────────┐
│ 🤔 AI 对指令的理解                │
├─────────────────────────────────┤
│ 我理解你要：                      │
│ 为"XX项目"创建"需求文档"          │
│                                 │
│ 目标：完成 PRD 初稿               │
│ 涉及Agent：平头叔(需求)           │
│ 预计完成：2小时内                │
├─────────────────────────────────┤
│ [✅ 确认执行] [✏️ 修改指令] [❌ 取消] │
└─────────────────────────────────┘
    ↓
用户选择"确认执行" → 真正发送任务
用户选择"修改指令" → 返回编辑
用户选择"取消" → 关闭弹窗
```

#### 数据来源
- 项目列表 → `/api/openclaw/projects`
- Agent 列表 → `/api/openclaw/agents`
- 历史任务 → `/api/openclaw/workspace`

#### 边界条件
- 指令模糊 → 显示"请补充项目名称或具体要求"
- Agent 不存在 → 提示"该Agent不可用"
- 网络失败 → 显示错误并保留用户输入

### C. Dashboard 数据展示

#### 目标
展示真实、实时的 Agent 和项目状态。

#### 展示内容
| 区块 | 数据 | API来源 |
|------|------|---------|
| Agent状态 | 头像/名称/负载/模型 | `/api/openclaw/agents` |
| 项目进度 | 名称/阶段/阻塞/负责人 | `/api/openclaw/projects` |
| 实时事件 | SSE推送的状态变更 | `/api/openclaw/events` |
| 统计数据 | Agent数/项目数/任务数 | 计算 |

#### 刷新策略
- **初始加载**：useEffect 调用 refresh()
- **实时更新**：SSE EventSource，收到消息后 250ms 刷新
- **手动刷新**：用户下拉刷新或点击刷新按钮

#### 边界条件
- API 加载中 → 显示骨架屏
- API 失败 → 显示错误状态 + 重试按钮
- 数据为空 → 显示"暂无数据"

### D. 新建项目流程

#### 目标
用户输入自然语言描述，自动解析并创建项目。

#### 交互流程
```
用户输入："做一个用户管理系统，包含登录、注册、个人资料"
    ↓
点击"创建" → 显示加载状态
    ↓
调用 POST /api/projects/parse 解析
    ↓
展示"解析预览"：
┌─────────────────────────────────┐
│ 📋 项目已解析                    │
├─────────────────────────────────┤
│ 项目名称：用户管理系统             │
│                                 │
│ 识别到的任务：                   │
│ □ 登录功能                      │
│ □ 注册功能                      │
│ □ 个人资料页面                   │
│                                 │
│ [👤 平头叔] - 需求分析           │
│ [👤 平头伯] - 产品规划           │
│ [👤 平头舅舅] - 技术研发         │
│ [👤 平头姑] - 测试               │
├─────────────────────────────────┤
│ [确认创建] [重新编辑] [取消]      │
└─────────────────────────────────┘
    ↓
用户确认 → 调用 POST /api/projects 创建
    ↓
创建成功 → 跳转到 ProjectRoom
```

#### API 端点
- `POST /api/projects/parse` - 解析自然语言
- `POST /api/projects` - 创建项目
- `GET /api/openclaw/agents` - 获取可分配 Agent

#### 边界条件
- 解析失败 → 显示"无法理解，请尝试更详细描述"
- 名称冲突 → 显示"项目名已存在，请修改"
- Agent 不可用 → 从建议中移除并提示

## 三、技术要求

### 前端数据流
```
useRealData() 
    ↓
API 调用 / 缓存
    ↓
React State
    ↓
syncRuntimeCollections() (同步到全局变量)
    ↓
组件渲染
```

### 严禁事项
- ❌ 硬编码 agent 名称（jeremy, 平头哥 等）
- ❌ 硬编码 agent ID（'1', '2' 等）
- ❌ 硬编码项目成员数组
- ❌ DEFAULT_* 数据作为主要数据源

### 删除范围
- 删除 `DEFAULT_AGENTS` 常量
- 删除 `DEFAULT_SESSIONS` 常量
- 删除 `DEFAULT_PROJECTS` 常量
- 删除 `DEFAULT_TASKS` 常量
- 保留 `DEFAULT_MODELS`（如果模型是固定配置）
