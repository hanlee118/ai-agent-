# 平台执行规范（可直接填写）

## 1. 平台定位
- 平台名称：协作项目平台（OCC）
- 平台背景：用于统一多 Agent 协作执行项目，强调真实数据、真实工具调用、全流程可追溯。
- 平台使命：以“可验证交付”为目标，让每个项目都按阶段门禁完成并形成可复用沉淀。

## 2. 执行引擎分工（executionEngines）
- OpenClaw：主执行引擎，负责项目流程推进、任务编排、交付落盘。
- Hermes：能力增强引擎，负责方法改进、提示词迭代、技能建议与自我升级闭环。
- GitLab：工程治理引擎，负责分支策略、CI 质量门禁、发布与审计追踪。

## 3. 调用优先级（executionPriority）
- 工具优先：有工具必须先用工具（例如设计优先 Stitch/Figma，研发优先代码与测试工具）。
- 技能次优先：无工具时优先装配并调用对应 Skill。
- 模型兜底：无工具且无技能时，按当前事项选择最优模型执行。
- 禁止伪造：禁止以假数据、假证据、伪链接冒充完成。

## 4. GitLab 治理（gitlabGovernance）
- 分支策略：feature/* -> release/* -> main，禁止直接在 main 开发。
- 合并门禁：必须通过 typecheck、smoke、closure 等验收脚本后才可合并。
- 冲突策略：出现冲突时以“最新验证通过代码”为准，保留审计记录。
- 发布审计：每次发布必须关联 Issue/项目 ID 与变更说明。

## 5. Hermes 自我升级闭环（hermesUpgradeLoop）
- 信号采集：收集项目阶段失败原因、回退原因、人工修订差异。
- 建议生成：Hermes 产出可执行升级建议（提示词、技能、流程、校验规则）。
- 灰度应用：建议先在单项目灰度启用并留存前后指标。
- 复盘固化：有效建议写回平台长期记忆并升级为平台规范。

## 6. 平台目标（goals）
- 每个项目全流程真实跑通（立项->分析->设计->开发->验收）。
- 每个阶段都有可验证产物与证据链接。
- 项目完成后自动形成可复用经验与长期记忆。
- 关键服务可用性、观测性达到可运营标准。

## 7. 执行原则（principles）
- 单项目闭环优先：一次只重点推进一个项目直到完成。
- 证据先于结论：所有“完成”声明必须附带证据。
- 失败可见：失败原因必须可观测、可追踪、可复现。
- 小步快跑：持续增量优化，避免大爆炸式改造。

## 8. 执行约束（constraints）
- 不允许跳过阶段门禁强行推进。
- 不允许使用占位数据通过验收。
- 不允许未验证即推送主分支。
- 高风险变更必须先在分支验证并保留回滚路径。

## 9. 禁止关键词（forbiddenKeywords）
- 假数据
- 模拟通过
- 占位已完成
- 跳过验证
- 手动伪造证据

## 10. 必须关键词（requiredKeywords）
- 工具调用记录
- 技能调用记录
- 模型选择依据
- 验收命令输出
- 回填与复盘
