# Agent 协作工作台 v1.0.1 需求文档

## 1. 文档信息

- 文档名称：Agent 协作工作台 v1.0.1 需求文档
- 文档日期：2026-03-26
- 文档用途：描述 v1.0.1 当前版本的已实现需求、业务规则、验收要求与版本边界
- 说明：本文件以仓库当前代码与已验证能力为准

## 2. 产品目标

v1.0.1 的目标是交付一套真正可使用的 Agent 协作平台，而不是只可演示的前端壳。平台需要支持用户在统一工作台中完成以下动作：

- 登录并进入受保护的管理平台
- 创建、查看和推进项目
- 查看真实 OpenClaw 项目、Agent、任务和文档
- 向单个 Agent 或多个 Agent 下达任务
- 在执行前进行理解确认或切换为自主执行
- 管理 Agent 的模型、SOUL、SOP、协作边界和 Token 限额
- 监控本地多工具会话与系统运行状态
- 基于自动化脚本验证关键业务闭环

## 3. 用户与角色

### 3.1 当前用户角色

- 平台管理员

### 3.2 当前 Agent 角色

平台必须支持展示和管理真实 OpenClaw 工作区中的 Agent，包括但不限于：

- `jeremy`
- `requirements_analyst`
- `product_manager`
- `architect`
- `rd_manager`
- `engineer`
- `qa_engineer`

系统不应将 Agent 名单硬编码为固定集合，而应优先以工作区实际数据为准。

## 4. 范围定义

### 4.1 已纳入 v1.0.1 的范围

- 管理员初始化与登录鉴权
- 统一 SaaS 工作台壳层
- 中英文切换
- 项目创建、预解析、确认和推进
- 项目组合与项目作战室
- OpenClaw 真实工作区项目与 Agent 展示
- Agent 指挥页、SOUL / SOP 编辑、模型切换与治理配置
- 长期记忆、调用日志、Token 用量与限额管理
- 系统健康、就绪度、运行配置、审计日志
- 本地多工具会话实时监控与成本治理面板
- 自动化 smoke / closure / acceptance 验证

### 4.2 不在 v1.0.1 范围内

- 多用户、多组织、多租户
- 完整 RBAC 权限体系
- 分布式任务调度与多节点执行器
- 企业级通知中心
- 与 GitHub、Slack、飞书、Jira 的正式双向集成
- PostgreSQL / Redis 的高可用集群化生产方案

## 5. 信息架构需求

平台一级模块必须包括：

- 总控首页
- 项目组合
- 项目作战室
- 团队工作区
- Agent 工作台
- Agent 指挥页
- 系统运营
- 审计轨迹
- 设置

平台界面必须满足以下结构要求：

- 使用统一的工作台壳层，而不是页面级碎片化布局
- 左侧提供工作区导航、项目快捷入口和 Agent 快捷入口
- 顶部提供搜索、状态、语言切换和操作入口
- 关键模块采用“主工作区 + 侧边情报栏 / 治理栏”布局
- 整体风格以 Slack 启发的信息优先级和 AI Studio 风格壳层为基础

## 6. 功能需求

### 6.1 认证与安全

- 系统首次启动时必须支持管理员密码初始化
- 初始化完成后，业务接口必须要求认证
- 未初始化状态下，接口必须返回 `428 system setup required`
- 未登录状态下，接口必须返回 `401 authentication required`
- 登录后前端必须通过 Cookie 保持会话

### 6.2 项目创建与理解确认

- 系统必须支持输入自然语言需求创建项目
- 创建前必须支持生成理解确认卡
- 理解确认卡至少包括：
  - 目标摘要
  - 约束条件
  - 风险
  - 建议团队
  - 执行建议
- 用户确认后必须可以创建项目

### 6.3 项目组合与项目作战室

- 系统必须支持查看项目列表
- 项目列表至少展示：
  - 项目名称
  - 状态
  - 当前阶段
  - 进度
  - 负责人
  - 摘要
- 项目组合页必须支持应用项目与 OpenClaw 项目的统一查看
- 项目详情必须展示：
  - 需求描述
  - 阶段
  - 任务
  - 交付物
  - 时间线
  - 实时输出流
- 系统必须支持项目审批、驳回、阶段提交、人工介入与恢复推进

### 6.4 OpenClaw 工作区联动

- 系统必须读取真实 `~/.openclaw` 或自定义 `OPENCLAW_ROOT` 工作区
- 系统必须展示工作区中的项目、Agent、任务、文档、最近消息与项目报告
- 系统必须支持查看项目阻塞项、参与 Agent 与任务分布
- 系统必须支持对真实工作区任务执行单条更新与批量更新
- 系统必须支持在平台内创建新的 OpenClaw Agent 并同步写入配置

### 6.5 Agent 工作台与 Agent 指挥页

- 系统必须展示每个 Agent 的：
  - 名称
  - 职位
  - 职责
  - 介绍
  - 当前模型
  - 当前状态
  - 当前任务
  - 会话数
  - 长期记忆数
  - Token 使用信息
- 系统必须支持在单个 Agent 页面完成：
  - 当前模型切换
  - 默认模型 / 回退模型配置
  - 执行模式切换
  - 是否需要确认配置
  - Token 限额配置
  - 记忆开关配置
  - 协作白名单配置
  - 工具白名单配置
  - SOUL 编辑
  - SOP 编辑

### 6.6 Agent 下单与执行确认

- 用户必须可以向单个 Agent 下达任务
- 用户必须可以向多个 Agent 批量下达任务
- 执行前必须支持生成理解确认结果
- 理解确认结果至少包括：
  - 目标
  - 执行计划
  - 步骤拆解
  - 风险
  - 建议动作
  - 推荐选项
- 当 Agent 处于 `confirm_first` 模式时，用户确认前不应直接执行
- 当 Agent 处于 `autonomous` 模式且关闭强制确认时，可持续推进

### 6.7 长期记忆与用量治理

- 平台必须持久化 Agent 长期记忆
- 长期记忆至少包括：
  - 类型
  - 摘要
  - 内容
  - 重要度
  - 标签
  - 来源
- 平台必须记录 Agent 调用日志
- 调用日志至少包括：
  - 模型
  - 输入 Token
  - 输出 Token
  - 总 Token
  - 状态
  - 指令类型
- 平台必须支持每日 Token 限额展示和剩余额度计算

### 6.8 系统运营与运行配置

- 平台必须支持配置运行提供方
- 当前运行提供方至少支持：
  - `scripted`
  - `openai-compatible`
- 平台必须支持保存 `apiBaseUrl`、`modelName`、`apiKey`
- 平台必须支持主动校验运行配置
- 平台必须提供健康检查与就绪度检查
- 就绪度检查至少包括：
  - 数据库路径
  - OpenClaw 配置文件存在性
  - 工作区存在性
  - Agent 数量
  - 项目数量
  - 告警列表

### 6.9 本地会话监控与成本治理

- 平台必须统一读取 Codex、Claude Code 与 OpenClaw 的最近会话
- 会话监控必须支持实时推送，不得只依赖固定轮询
- 系统运营页必须提供按工具聚合的成本治理面板
- 成本治理面板至少展示：
  - 工具维度会话数
  - 活跃 / 空闲状态
  - 总 Token
  - 已知成本
  - 估算成本
  - 最近会话摘要

### 6.10 审计与追踪

- 平台必须记录关键操作审计日志
- 审计日志至少包括：
  - 操作人类型
  - 操作标签
  - 动作
  - 资源类型
  - 资源 ID
  - 摘要
  - 详情
- 平台必须支持通过系统运营或审计页面查询关键记录

### 6.11 自动化验收

- 平台必须支持 `pnpm verify:smoke`
- 平台必须支持 `pnpm verify:closure`
- 平台必须支持 `pnpm test:acceptance`
- 自动化验证必须覆盖项目、任务、OpenClaw、Agent 指挥和运行配置等关键链路

## 7. 验收标准

- 管理员可完成初始化、登录与受保护访问
- 项目可被创建、查看、推进、审批与回写
- OpenClaw 项目、Agent、任务和文档可被真实读取
- 单 Agent 指挥链路可完成模型切换、确认执行、消息发送与治理配置保存
- 系统运营页可展示健康、就绪度、实时会话和成本治理信息
- 自动化脚本通过后，方可视为当前版本达到可验收状态

## 8. 当前版本边界说明

v1.0.1 已经达到“真实工作台”而非“演示页面”的要求，但当前仍聚焦单管理员、本地 / 单机部署、OpenClaw 工作区联动与 Agent 治理主链路。更大规模的组织协同、外部系统深度集成与企业级高可用能力，将在后续版本中继续推进。
