# OpenClaw Command Center 1.0 UI 设计

## 1. 视觉方向

产品定位不是“普通后台”，而是“数字作战室”。因此界面采用深海蓝与电流青为主基调，用暖橙和警示红承接风险与干预动作，让系统既像控制台又不失可读性。

## 2. 设计原则

- 观测优先：实时输出永远是视觉焦点
- 控制明确：审批、暂停、恢复要有强烈层级
- 状态可扫读：用户 3 秒内能看懂项目健康状况
- 信息分层：概览看状态，进入观测室看内容

## 3. 颜色与字体

### 3.1 颜色

- 背景：`#07111F`
- 面板：`#0F1C2E`
- 次级面板：`#15263D`
- 主强调：`#51E5FF`
- 成功：`#42D392`
- 警示：`#FFB84D`
- 危险：`#FF6B6B`
- 主文本：`#E8F0FF`
- 次文本：`#8DA3C2`

### 3.2 字体

- 标题：`Sora`
- 正文：`Noto Sans SC`
- 数据与代码：`JetBrains Mono`

## 4. 页面结构

### 4.1 仪表盘

- 顶部 Hero 区：产品口号、项目数量、实时状态
- 左侧主区域：新项目输入与理解确认卡
- 右侧侧栏：待审批项目和团队健康概览
- 下方卡片墙：活跃项目、最近完成项目

### 4.2 项目观测室

- 左栏宽 280px：项目摘要、阶段列表、团队在线状态
- 中栏弹性布局：直播输出、当前交付物摘要、阶段说明
- 右栏宽 360px：审批卡、时间轴、干预面板

### 4.3 Agent 中心

- 卡片网格展示角色
- 详情中采用“能力条 + 绩效趋势 + 风格标签”组合，而不是复杂图表优先

## 5. 关键交互

### 5.1 理解确认卡

- 点击“解析需求”后显示
- 包含关键词、约束、风险、建议团队
- 用户确认后才能创建项目

### 5.2 实时直播区

- 模拟打字机渐进输出
- 显示当前角色、开始时间、已工作时长
- 重要结论可用高亮块插入

### 5.3 紧急介入

- 采用高对比危险区块
- 输入指令后立即反馈“项目已暂停”
- 恢复按钮与暂停按钮分色处理，避免误触

## 6. 响应式策略

- 桌面端优先使用 3 栏布局
- 平板端折叠右栏为抽屉
- 手机端只保留阶段、实时输出和审批核心能力
