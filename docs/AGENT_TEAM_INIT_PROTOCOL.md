# Agent Team 立项协议 v1

更新时间：2026-04-04

## 适用范围

适用于 `INIT` 和 `ANALYSIS` 阶段，覆盖从原始需求进入系统，到形成可执行项目结论为止的上半程协作。

## 目标

把一句话需求、用户旅程、会议纪要或零散想法，转成可进入设计和研发的项目输入。

## 角色分工

1. `ROLE_PM`
   - 负责 kickoff、项目章程、阶段边界、推进节奏
2. `ROLE_ANALYST`
   - 负责需求澄清、边界判断、约束识别、风险识别
3. `ROLE_PRODUCT`
   - 负责价值判断、优先级、验收标准、方案取舍

## 立项总原则

1. 先澄清，再承诺。
2. 先定义边界，再分配执行。
3. 先识别风险，再默认推进。
4. 当前项目事实优先于历史记忆。
5. 长期记忆可参考，但只允许当前项目或高关联经验参与。

## 输入来源

允许的输入：

1. 一句话需求
2. 用户旅程
3. 会议纪要
4. 当前产品背景
5. 当前项目相关长期记忆

禁止直接沿用的输入：

1. 低相关旧项目章程
2. 旧项目客户汇报模板
3. 默认业务设定
4. 无法溯源的历史结论

## INIT 协议

### 阶段目标

产出项目章程，让团队知道“要解决什么、边界在哪里、谁负责推进”。

### 必做事项

1. 明确项目目标。
2. 明确项目范围与非范围。
3. 明确核心参与角色。
4. 明确阶段推进规则。
5. 明确待补充信息与风险空白。

### 标准产物

1. 项目目标
2. 范围 / 非范围
3. 初始角色分工
4. 初始阶段计划
5. 待澄清问题列表

### INIT 门禁

以下任一缺失，不允许进入 `ANALYSIS`：

1. 项目目标
2. 范围边界
3. 阶段负责人
4. 待确认项

## ANALYSIS 协议

### 阶段目标

把需求变成能直接交给设计和研发继续工作的结构化输入。

### 必做事项

1. 抽取目标、边界、约束、风险。
2. 明确成功标准与验收标准。
3. 识别依赖、前置条件和关键里程碑。
4. 区分事实、假设和待确认项。
5. 给出优先级与取舍依据。

### 标准产物

1. 需求分析结论
2. 范围与边界说明
3. 约束条件清单
4. 风险清单
5. 验收标准
6. 阶段建议与优先级

### ANALYSIS 门禁

以下任一缺失，不允许进入 `DESIGN`：

1. 边界不清
2. 验收标准缺失
3. 风险未标注
4. 关键约束未确认

## 协作交接卡

立项与分析阶段输出必须带固定字段：

1. `factsConfirmed`
2. `assumptions`
3. `decisions`
4. `handoff`
5. `openQuestions`

要求：

1. `factsConfirmed` 只写已确认输入。
2. `assumptions` 只写当前推断。
3. `decisions` 写清为什么这样定。
4. `handoff` 必须能直接交给设计阶段。
5. `openQuestions` 必须保留风险空白，不能假装都已解决。

## 记忆使用协议

1. 长期记忆保持开启。
2. 仅允许引用当前项目记忆或高关联经验。
3. 旧项目背景、旧需求结论、旧视觉风格不得直接迁移。
4. 如果当前需求和长期记忆冲突，必须显式标注冲突。

## 输出质量标准

1. 不得把模糊话术直接写成正式需求。
2. 不得跳过边界与风险讨论。
3. 不得用模板腔调替代项目判断。
4. 输出必须能被下游设计和研发直接消费。

## 推荐执行方式

1. `ROLE_PM` 先完成 kickoff 与项目章程。
2. `ROLE_ANALYST` 形成分析主结论。
3. `ROLE_PRODUCT` 补齐价值、优先级、验收标准。
4. 输出交由设计阶段继续推进。
