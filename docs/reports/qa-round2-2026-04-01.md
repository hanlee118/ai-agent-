# QA Round2 报告（2026-04-01）

## 目标
第2轮聚焦稳定性与门禁强化，要求“发现问题即修复”，并验证回归可重复通过。

## 本轮发现与修复

### 1) 路由测试分支不稳定 + 长耗时（门禁路径）
- 现象：`test:routes` 中 `deeper branches with real-model gate failure` 偶发走到 `STAGE_TEMPLATE_VALIDATION_FAILED`，且耗时可达 100s+。
- 根因：
  - 测试 DB 的 `SystemConfig` 可能遗留真实模型配置，导致门禁路径不稳定。
  - `reject` 分支在 test 环境仍可能触发真实模型调用，导致慢查询/长等待。
- 修复：
  - 在测试初始化 SQL 强制 `SystemConfig` 设为 scripted。
  - `assertRealModelRuntimeReadyForGate` 在 `NODE_ENV=test` 且 `MODEL_PROVIDER!=openai-compatible` 时快速失败。
  - `rejectProjectStage` 在 test 环境使用确定性返工输出，跳过真实模型调用。

### 2) 测试环境异步回填噪音
- 现象：模板校验失败后自动触发异步 `reconcile`，可能在 teardown 后继续写库，造成噪音。
- 修复：`NODE_ENV=test` 下关闭 approve 路径的自动 `reconcile` 异步触发。

### 3) 烟测可重复性
- 现象：`verify:smoke` 在 API 未预启动时直接失败。
- 修复：`verify-smoke.sh` 增加 `ensure_api_ready`，自动拉起/回收 daemon。

## 关键改动文件
- `apps/api/src/data/repository.ts`
- `apps/api/src/routes/projects.ts`
- `apps/api/src/routes/routes.test.ts`
