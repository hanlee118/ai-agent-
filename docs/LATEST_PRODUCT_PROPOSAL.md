# 最新产品方案

文档版本：Latest  
更新时间：2026-04-01

## 1. 产品名称与定位

产品名称：Agent Collaboration Workbench  
中文建议名：Agent 协作工作台

定位：
- 面向真实交付场景的多 Agent 协作平台
- 强调“执行收敛 + 质量门禁 + 外部协同 + 验收证据”
- 不是聊天工具，而是可运营的 Agent 团队工作流系统

## 2. 本轮（相对 2026-03-30）最大升级

从“流程可推进”升级到“流程可收敛、可恢复、可验收”：
- 推进链路具备风暴检测与软恢复
- 真实模型门禁从软约束变硬门禁
- 角色级白名单与最小成功次数纳入阶段验收
- 门禁失败可执行动作链化（recoveryPlan）
- GitLab Harness 形成外部工单闭环
- 健康检查内置真实模型自检与一键修复指引
- 增加可重复通过验收脚本

## 3. 核心用户价值

### 3.1 对管理者（PM/负责人）

- 明确知道项目为何卡住、如何修复、下一步做什么
- 门禁失败不是“黑盒失败”，而是“可执行步骤”
- 验收结果可重复、可对比、可归档

### 3.2 对执行团队（设计/研发/测试）

- 按角色执行证据完成质量闭环
- 阶段交付与审查流程更清晰
- 外部 GitLab 协同自动同步，减少双写

### 3.3 对平台运维

- 运行时健康检查带修复指引
- 真实模型链路 readiness 可快速定位
- 故障恢复策略减少长时间阻塞

## 4. 产品工作流（当前实现）

1. 用户创建项目（自然语言解析）
2. 平台按阶段组织多角色执行
3. 交付物提交后进入阶段审批
4. 门禁校验（真实模型 + 角色证据 + 模型白名单）
5. 失败返回 `requiredActions + recoveryPlan`
6. 执行修复动作后回到审批
7. DEV/ACCEPT 自动同步 GitLab Harness
8. 项目完成生成验收报告与最终产物

## 5. 功能结构（当前落地）

### 5.1 协作执行层

- Projects / Project Room
- 阶段推进（手动 + 自动）
- 审批、驳回、介入、恢复
- 任务板、时间线、交付物

### 5.2 质量门禁层

- 真实模型强门禁（可开关）
- ROLE_PM 强制执行证据
- ROLE_DESIGN/ARCH/DEV/QA 白名单与最小成功次数
- 模板质量校验 + 设计审查卡门禁

### 5.3 收敛恢复层

- `/advance` 退避、风暴检测、软恢复
- 超时/网络抖动场景自动重试
- `REAL_MODEL_GATE_FAILED` 动作链化修复

### 5.4 外部协同层

- GitLab Harness issue 同步
- webhook 回写任务状态
- 完成自动关单（closeOnComplete）

### 5.5 运维保障层

- 一键健康检查与 latest 报告
- 真实模型自检 + 修复步骤
- 可重复验收脚本

## 6. 产品成功标准

### 6.1 交付成功标准

- 关键回归：`typecheck/routes/smoke` 全通过
- 健康检查：`pnpm health:check` 报告可读可执行
- 可重复验收：`pnpm verify:repeatable:018` 输出 `ok=true`

### 6.2 质量成功标准

- 阶段验收不再允许 scripted/degraded 假通过
- 门禁失败给出可收敛修复路径
- 外部工单状态与平台任务状态一致

## 7. 近期路线（下一阶段）

- 强化 `verify:real-data:round2` 全绿路径（在真实模型配置就绪后）
- 增加多项目并发场景下的推进公平性与限流策略
- 补齐组织级权限与团队协作治理能力

## 8. 结论

当前版本已经从“演示型协作台”进入“可控可验收的工程型协作平台”阶段。  
后续主要增量将聚焦在真实模型链路稳定性与组织化治理能力，而不是基础流程补课。
