# Agent 协作工作台 v1.0.0 需求文档

## 1. 文档信息

- 文档名称：Agent 协作工作台 v1.0.0 需求文档
- 文档日期：2026-03-26
- 文档用途：描述当前版本已实现的需求范围、业务规则、验收标准与未纳入范围
- 说明：本文件以当前代码与实际可运行能力为准，不再使用纯目标态描述

## 2. 产品目标

v1.0.0 的目标是交付一个真实可用的 Agent 协作平台，而不是演示壳子。平台需要让用户在一个统一工作台中完成以下动作：

- 登录并进入受保护的管理平台
- 创建和跟踪项目
- 查看真实 OpenClaw 项目、Agent、任务和文档
- 向单个 Agent 或多个 Agent 下达任务
- 在关键执行前进行理解确认
- 管理 Agent 的模型、SOUL、SOP、职责、白名单和 Token 策略
- 查看系统健康、就绪度与审计日志

## 3. 用户与角色

### 3.1 当前用户角色

- 平台管理员

### 3.2 当前 Agent 角色

平台支持展示和管理真实 OpenClaw 工作区中的 Agent，包括但不限于：

- `jeremy`
- `requirements_analyst`
- `product_manager`
- `architect`
- `rd_manager`
- `engineer`
- `qa_engineer`

平台不强制写死 Agent 名单，而是以工作区实际数据为主。

## 4. 范围定义

### 4.1 已纳入 v1.0.0 的范围

- 认证初始化与登录
- 项目创建与预解析
- 项目组合页
- 项目作战室
- OpenClaw 团队工作区
- Agent 列表与 Agent 指挥页
- SOUL / SOP 编辑
- 模型切换与运行策略配置
- Agent 记忆与用量记录
- 批量任务更新
- 系统健康、就绪度、运行配置
- 审计日志
- 中英文切换

### 4.2 不在 v1.0.0 范围内

- 多用户、多组织、多租户
- 完整 RBAC 权限体系
- 分布式任务队列
- 企业级通知中心
- GitHub / 飞书 / Slack 正式双向集成
- PostgreSQL / Redis 的生产集群化部署

## 5. 信息架构需求

平台一级模块必须包括：

- 总控首页
- 项目组合
- 团队工作区
- Agent 工作台
- Agent 指挥页
- 系统运营
- 审计轨迹
- 设置

平台需要支持从项目视角与 Agent 视角两条主线进入，避免只能通过聊天框使用系统。

## 6. 功能需求

### 6.1 认证与安全

- 系统首次启动时，必须支持管理员密码初始化。
- 初始化后，所有 `/api` 业务接口必须要求认证。
- 未初始化状态下，系统必须返回 `428 system setup required`。
- 未登录状态下，系统必须返回 `401 authentication required`。
- 登录后，前端应通过 Cookie 保持会话状态。

### 6.2 项目创建与预解析

- 用户输入自然语言需求后，系统必须支持预解析。
- 预解析结果至少包含：
  - 关键词
  - 约束
  - 风险
  - 建议团队
  - 需求摘要
- 用户确认后，系统必须可以创建项目。

### 6.3 项目组合与项目作战室

- 系统必须支持查看项目列表。
- 每个项目至少展示：
  - 项目名称
  - 状态
  - 当前阶段
  - 进度
  - 是否待审批
  - 当前负责人
  - 摘要
- 项目详情必须展示：
  - 需求描述
  - 阶段列表
  - 任务列表
  - 交付物
  - 时间线
  - 实时输出流
- 系统必须支持项目审批、驳回、阶段提交、介入和恢复。

### 6.4 OpenClaw 工作区联动

- 系统必须读取真实 `~/.openclaw` 工作区中的项目与 Agent。
- 工作区项目至少展示：
  - 项目名称
  - 路径
  - 状态
  - 进度
  - 任务数
  - 阻塞数
  - 参与 Agent
  - 当前焦点
- 系统必须支持查看工作区项目文档摘要与项目报告。
- 系统必须支持对真实工作区任务执行单条或批量更新。

### 6.5 Agent 列表与 Agent 指挥页

- 系统必须支持展示每个 Agent 的：
  - 名称
  - 职位
  - 职责
  - 介绍
  - 当前模型
  - 状态
  - 当前任务
  - 会话数量
  - 长期记忆数量
  - Token 使用情况
- 系统必须支持在单独 Agent 页面完成：
  - 模型切换
  - 默认模型 / 回退模型配置
  - 执行模式切换
  - 是否需要确认配置
  - 是否自动通过微小步骤
  - Token 限额设置
  - 记忆开关设置
  - 协作白名单设置
  - 工具白名单设置
  - SOUL 编辑
  - SOP 编辑

### 6.6 Agent 下单与确认机制

- 用户必须可以向单个 Agent 下达任务。
- 用户必须可以向多个 Agent 批量下达任务。
- 单个 Agent 执行前，系统必须支持生成理解确认结果。
- 理解确认结果至少包括：
  - 目标
  - 执行计划
  - 步骤拆解
  - 风险
  - 建议动作
  - 推荐选项
- 当 Agent 处于 `confirm_first` 模式时，用户确认前不应直接执行。
- 当 Agent 处于 `autonomous` 模式且关闭强制确认时，可持续执行。

### 6.7 Agent 长期记忆与用量治理

- 平台必须持久化 Agent 长期记忆。
- 长期记忆至少包括：
  - 类型
  - 摘要
  - 内容
  - 重要度
  - 标签
  - 来源
- 平台必须记录 Agent 调用日志。
- 调用日志至少包括：
  - 模型
  - 输入 Token
  - 输出 Token
  - 总 Token
  - 状态
  - 指令类型
- 平台必须支持每日 Token 限额展示和剩余额度计算。

### 6.8 运行配置与系统运营

- 平台必须支持配置运行提供方。
- 当前运行提供方至少支持：
  - `scripted`
  - `openai-compatible`
- 平台必须支持保存 `apiBaseUrl`、`modelName`、`apiKey`。
- 平台必须支持主动校验运行配置。
- 平台必须提供健康检查。
- 平台必须提供就绪度检查，包括：
  - 数据库路径与存在性
  - OpenClaw 配置文件存在性
  - 工作区存在性
  - Agent 数量
  - 项目数量
  - 告警列表

### 6.9 审计与追踪

- 平台必须记录关键操作审计日志。
- 审计日志至少包括：
  - 操作人类型
  - 操作标签
  - 动作
  - 资源类型
  - 资源 ID
  - 摘要
  - 详情
  - 请求 ID
  - IP
  - 时间

### 6.10 国际化

- 平台必须支持中英文切换。
- 切换结果必须存储在浏览器本地。
- 页面框架级文案必须覆盖双语。

## 7. 非功能需求

### 7.1 可部署性

- 平台必须支持 `pnpm build` 后以单服务形式运行。
- 后端必须能够直接托管前端构建产物。

### 7.2 可观测性

- API 必须支持 `health` 与 `ready` 接口。
- 每个请求必须输出结构化访问日志。
- 响应头必须包含 `x-request-id`。

### 7.3 数据持久化

- 所有治理配置、认证信息、记忆、日志和项目主数据必须进入数据库。
- 工作区内容以 OpenClaw 本地文件和配置为真实来源。

### 7.4 安全性

- 管理员密码不得明文存储。
- API Key 不得明文暴露到前端。
- 运行配置中的密钥需要通过本地密钥机制保护。

## 8. 验收标准

满足以下条件可视为 v1.0.0 达到验收标准：

- 可以初始化管理员并正常登录
- 可以打开首页、项目、Agent、系统、审计等核心页面
- 可以看到真实 OpenClaw 项目与真实 Agent
- 可以看到 `jeremy`
- 可以在 Agent 指挥页切换模型和执行模式
- 可以生成理解确认卡并对 Agent 下单
- 可以编辑 SOUL 和 SOP
- 可以看到长期记忆与用量日志
- 可以看到系统健康与就绪度
- 可以正常切换中英文
- `pnpm typecheck`、`pnpm build`、`pnpm verify:local` 通过

## 9. 当前已知延后项

- 多管理员和组织协作
- 更细粒度的审批流程引擎
- 更强的移动端布局适配
- 外部服务统一 OAuth 登录
- 面向生产域名的正式隧道和反向代理方案

## 10. 版本结论

v1.0.0 已满足“真实可用的 Agent 工作台”这一目标。它不是最终形态，但已经是具备闭环能力、可上线到本地生产环境、可继续扩展的第一个正式版本。
