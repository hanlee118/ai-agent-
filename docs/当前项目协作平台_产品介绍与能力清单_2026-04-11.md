# 当前项目协作平台产品介绍与能力清单

> 文档版本：v1.0
> 更新时间：2026-04-11
> 对应平台：Agent Collaboration Workbench（项目协作平台）

## 1. 产品定位

项目协作平台是一个面向“多 Agent + 多角色 + 多阶段交付”的工程化协同系统。
它不是单纯聊天工具，而是把项目推进、执行治理、模型路由、质量门禁、审计追踪和工作区联动整合在一个可运行平台中。

核心目标：
- 让项目从 `INIT -> ANALYSIS -> DESIGN -> DEV -> ACCEPT` 可持续推进。
- 让每个阶段输出可验证交付，而不是只产生文本。
- 让模型调用、Agent 行为、协作证据和审批决策可追溯。

## 2. 当前已实现能力（平台能力）

### 2.1 项目协作与阶段推进

已实现：
- 自然语言创建项目与需求解析。
- 阶段化推进流程（INIT/ANALYSIS/DESIGN/DEV/ACCEPT）。
- 项目作战室（Project Room）统一查看任务、阶段、交付状态。
- 项目干预、恢复、关闭、审批等管理动作。

价值：
- 让项目管理从“状态描述”升级为“可执行状态机”。

### 2.2 Agent 指挥与协同执行

已实现：
- Agent 列表、Agent 详情、SLA 与执行态可视化。
- Agent 指挥消息下发（单发/批量）。
- Agent 设置中心：模型、执行模式、工具白名单、协作白名单、Token 限额。
- Agent 记忆读写与文档能力（如 SOUL/SOP 文档维护）。

价值：
- 把“角色协作”从口头协同变成可配置、可复用、可审计的执行机制。

### 2.3 运行时与模型治理

已实现：
- 运行模式支持：`scripted` 与 `openai-compatible`。
- Runtime 配置管理：模型、Base URL、API Key、来源状态。
- Runtime 连通性校验与健康状态回显。
- 模型路由自检与自愈（包括占位配置修复）。
- 设计阶段模型策略与优先级策略能力。

价值：
- 降低“模型可用但系统不可用”的运维风险，提升真实执行稳定性。

### 2.4 设计能力链路（含 Stitch）

已实现：
- 设计阶段可走 Stitch 集成链路（Google Stitch MCP SDK 接入）。
- 支持 Stitch 请求构建、代理环境识别、传输错误识别与重试/冷却控制。
- 设计阶段具备“模型降级与兜底策略”，保证阶段可继续推进。

价值：
- 设计阶段从“主观草稿”升级为“可生成、可验证、可回退”的稳定流程。

### 2.5 OpenClaw 工作区联动

已实现：
- 工作区状态、项目、任务、Agent 数据读取。
- 项目任务更新（单任务/批量）和项目报告构建。
- OpenClaw Agent 消息执行链路集成。
- 模型路由修复（含 OpenAI 兼容网关 `X-Group` 修正与 key 同步策略）。

价值：
- 平台可直接对接真实执行工作区，而非仅本地模拟数据。

### 2.6 执行协议、质量门禁与审计

已实现：
- 执行协议开关（技能证据、协作交接、降级写入阻断等）。
- 阶段门禁与交付约束（避免无效交付误过审）。
- 审计日志与系统事件追踪。
- 系统健康检查、运行状态监控与问题定位辅助能力。

价值：
- 让“质量标准”可配置、可执行、可复盘。

### 2.7 设置中心（Settings）

已实现：
- 设置中心统一管理：界面偏好、运行时配置、执行协议、产品上下文。
- 自主模式偏好下发到 Agent（支持范围控制，如全部/核心/设计）。
- 保存策略支持本地偏好与平台配置协同。

价值：
- 实现“治理配置集中化”，降低跨页面配置漂移风险。

### 2.8 集成与运维能力

已实现：
- GitLab Harness 链路接入能力（用于任务联动与闭环）。
- 本地守护脚本：服务启动、停止、状态检查。
- 健康检查、烟测脚本与发布前验证流程。

价值：
- 支撑平台从开发态走向可持续运行态。

## 3. 应用能力（可落地使用场景）

### 场景 A：新产品从需求到验收

可应用：
- PM 通过自然语言立项。
- 平台自动拆分阶段并分配角色执行。
- 设计阶段走 Stitch/模型能力生成方案。
- DEV/ACCEPT 阶段按门禁与审计闭环完成交付。

### 场景 B：存量系统重构项目

可应用：
- 先用 ANALYSIS 阶段沉淀问题与约束。
- DESIGN 阶段沉淀重构方案与交互规范。
- DEV 阶段跟踪多角色并行执行，减少口头沟通损耗。

### 场景 C：跨角色协同治理

可应用：
- 对不同 Agent 设定不同执行模式与工具边界。
- 对关键环节开启门禁，避免“低质量快速推进”。
- 用审计记录做问题复盘与过程改进。

### 场景 D：模型与网关运营

可应用：
- 统一管理模型路由、运行配置与可用性校验。
- 在模型波动时自动切换或降级，保障主流程不中断。
- 通过自检/自愈功能降低配置腐化导致的不可用风险。

## 5. 当前边界与说明

- 平台已具备“可运行 + 可协作 + 可治理”的主线能力，但仍建议持续进行回归验证与策略迭代。
- 不同模型或外部服务的可用性会受上游渠道状态影响，平台已提供路由修复、降级与健康校验能力用于缓冲风险。
- 对外发布时建议同步版本说明、能力清单与已知边界，确保预期一致。

## 6. 一句话对外介绍（可直接复用）

Agent Collaboration Workbench 是一个把多 Agent 协作、项目阶段推进、模型治理、质量门禁与审计追踪整合到一起的项目协作平台，能够把从需求到验收的全过程变成可执行、可验证、可追溯的交付闭环。
