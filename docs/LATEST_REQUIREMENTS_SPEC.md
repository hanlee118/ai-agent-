# 最新需求文档

文档版本：Latest  
更新时间：2026-03-26

## 1. 文档目标

本需求文档用于定义 Agent 协作工作台当前最新版本的范围、核心需求、关键流程和验收标准。  
文档以当前已实现能力为基础，同时覆盖后续继续迭代时必须保持的产品边界。

## 2. 产品目标

- 构建一个可连接真实 OpenClaw 工作区的 Agent 团队协作平台
- 支持项目创建、项目推进、Agent 指挥、运营治理与审计追踪
- 将“对话式下达任务”升级为“可确认、可执行、可追踪的工作流”

## 3. 范围定义

### 3.1 当前版本必须覆盖

- 认证登录
- 项目创建与项目总览
- 项目作战室
- 真实 OpenClaw 工作区展示
- Agent 名册
- 单 Agent 指挥页
- 运行配置与系统运营
- 审计日志
- 双语切换

### 3.2 当前版本暂不强制

- 多租户
- 组织级权限体系
- 财务结算系统
- 企业 SSO
- 复杂审批工作流编排器

## 4. 核心对象

### 4.1 Project

必须包含：

- 项目 ID
- 名称
- 描述
- 状态
- 当前阶段
- 当前进度
- 更新时间
- 待审批状态
- 任务数量

### 4.2 Agent

必须包含：

- Agent ID
- 名称
- 职位
- 介绍
- 职责
- 当前模型
- 执行模式
- 当前状态
- 当前任务
- 会话数量
- 阻塞任务数量
- 工具白名单
- 协作白名单

### 4.3 Task

必须包含：

- 任务 ID
- 所属项目
- 所属 Agent
- 标题
- 状态
- 进度
- 更新时间

### 4.4 Governance

必须包含：

- Token 限额
- 默认模型
- 回退模型
- 执行策略
- 记忆开关
- 审计日志

## 5. 功能需求

## 5.1 认证与访问

### FR-001 登录

- 系统必须支持管理员密码初始化与登录
- 系统必须支持受保护接口鉴权

验收：

- 未登录访问受保护接口时返回 401
- 登录后可访问项目、Agent、系统接口

## 5.2 首页总控

### FR-010 Dashboard

- 首页必须展示平台关键指标
- 首页必须支持自然语言项目创建
- 首页必须支持生成理解确认卡
- 首页必须支持进入项目、Agent、系统等模块

验收：

- 输入项目需求后可生成解析结果
- 点击确认后可创建项目并进入详情

## 5.3 项目组合

### FR-020 Projects

- 系统必须统一展示应用内项目与 OpenClaw 工作区项目
- 必须支持搜索
- 必须支持来源筛选
- 必须支持状态筛选
- 必须展示项目进度、任务数、阻塞数、更新时间

验收：

- 用户可快速找到目标项目
- 可从项目卡片进入项目作战室或工作区视图

## 5.4 项目作战室

### FR-030 Project Room

- 必须展示项目阶段、任务、时间线、交付物
- 必须支持审批、驳回、恢复、人工介入
- 必须支持查看项目消息与活动

验收：

- 项目状态可推进
- 关键审批动作会留下审计痕迹

## 5.5 OpenClaw 工作区

### FR-040 Workspace

- 必须读取真实 OpenClaw 工作区中的项目和 Agent
- 必须展示真实任务、文档、会话和状态
- 必须支持对部分任务进行回写更新

验收：

- 能看到真实工作区中的项目、任务与 Agent
- 修改后能通过接口回写

## 5.6 Agent 名册

### FR-050 Agents

- 必须展示当前受管 Agent 团队
- 必须支持搜索与筛选
- 必须展示任务负载、模型、执行策略、当前任务
- 必须支持创建新 Agent

验收：

- 用户可快速定位重点 Agent
- 用户可从页面创建新 Agent 并在列表中看到

## 5.7 单 Agent 指挥

### FR-060 Agent Commander

- 必须支持单独页面查看 Agent
- 必须支持独立切换模型
- 必须支持切换执行模式
- 必须支持治理信息编辑
- 必须支持 SOUL / SOP 编辑
- 必须支持长期记忆查看和新增
- 必须支持使用日志查看
- 必须支持直接下发任务
- 必须支持“先理解再执行”
- 必须支持“直接由你决定”

验收：

- `confirm_first` 模式下，发送指令后出现理解确认卡
- 确认卡必须包含结构化确认选项
- 用户可通过选项完成确认执行、修改、仅分析、换模型后重试
- `autonomous` 模式下，Agent 可直接执行

## 5.8 运营与系统治理

### FR-070 System

- 必须展示运行配置
- 必须支持模型供应商配置与校验
- 必须展示系统健康状态
- 必须展示平台就绪度
- 必须展示本地 Agent 会话监控
- 必须展示成本治理信息
- 本地会话监控必须支持实时推送

验收：

- 系统页可以看到运行配置、健康、监控和成本信息
- SSE 可推送本地监控快照

## 5.9 审计

### FR-080 Audit

- 必须记录关键治理动作
- 必须可查询审计日志

验收：

- 至少可查询配置更新、Agent 指令、关键系统动作

## 5.10 设置

### FR-090 Settings

- 必须支持中英文切换
- 必须支持工作台基础偏好设置

验收：

- 切换语言后核心页面文本同步切换

## 6. 非功能需求

### NFR-001 可用性

- 页面信息结构必须清晰
- 主要模块必须可导航、可理解、可操作

### NFR-002 稳定性

- 类型检查与构建必须通过
- 基础烟测必须通过

### NFR-003 可观测性

- 系统必须暴露健康检查与就绪度检查
- 关键行为必须有审计记录

### NFR-004 可治理性

- Agent 模型、Token、执行模式、记忆、权限必须可管理

### NFR-005 国际化

- 平台必须支持中英文双语

## 7. 关键流程

## 7.1 创建项目流程

1. 用户输入需求
2. 系统生成理解确认卡
3. 用户确认创建
4. 系统建立项目并进入项目作战室

## 7.2 Agent 接单流程

1. 用户进入单 Agent 指挥页
2. 用户输入任务
3. 系统生成理解确认卡
4. 用户通过结构化选项确认下一步
5. Agent 开始执行或继续等待

## 7.3 Agent 自主执行流程

1. 用户将执行模式切为 `autonomous`
2. 用户下发任务
3. Agent 直接执行
4. 平台记录日志、使用量和状态变化

## 7.4 系统治理流程

1. 运营人员进入系统页
2. 查看运行配置、健康状态、监控与成本
3. 执行配置更新或连通性校验
4. 系统记录审计日志

## 8. 验收标准

当前最新版本至少应满足以下验收：

- 能登录
- 能创建项目
- 能查看项目组合
- 能查看真实 OpenClaw 工作区项目与 Agent
- 能进入 Agent 指挥页
- 能切换模型
- 能切换执行模式
- 能生成理解确认卡
- 能通过结构化确认选项继续执行
- 能查看与新增长期记忆
- 能查看系统健康与实时本地监控
- 能通过 `typecheck`、`build`、`verify:smoke`

## 9. 本轮最新补强点

相较此前版本，本轮需求实现重点已经包括：

- 项目页的 SaaS 化重构
- Agent 页的团队名册化重构
- Agent 指挥页的结构化确认交互补强
- 样式与骨架进一步向 AI Studio 方案对齐
