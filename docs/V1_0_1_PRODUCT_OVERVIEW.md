# Agent 协作工作台 v1.0.1 产品说明文档

## 1. 文档信息

- 产品名称：Agent 协作工作台
- 版本号：v1.0.1
- 文档日期：2026-03-26
- 文档定位：面向验收、交付、部署与运营的最新版产品说明
- 当前形态：可登录、可调用真实 OpenClaw 工作区、可进行系统运营治理的 Agent 团队协作工作台

## 2. 产品定义

Agent 协作工作台是一套围绕“项目协作 + Agent 指挥 + 运行治理 + OpenClaw 联动”构建的工作平台。它的目标不是提供单一聊天入口，而是让用户像管理一支真实数字团队一样，去查看项目进度、分配任务、切换模型、维护 SOUL/SOP、保存长期记忆、控制 Token 用量并审计关键操作。

v1.0.1 在 v1.0.0 的基础上，进一步完成了两个关键升级：

- 将工作台主壳层统一收敛到更接近 Slack / AI Studio 启发的 SaaS 协作结构，修正旧版页面骨架残留问题
- 新增闭环验收能力，确保项目流、Agent 指挥流、OpenClaw 工作区流和运行配置流不只是“页面存在”，而是可以被自动验证

## 3. 产品价值

- 让项目、Agent、任务、文档与系统状态在同一工作台中可观测
- 让管理员可以对 Agent 的模型、执行策略、Token 限额与长期记忆进行治理
- 让 OpenClaw 中的真实项目、真实 Agent 与真实任务进入统一控制面
- 让平台具备从本地生产运行到持续发布的实际交付能力

## 4. v1.0.1 已实现能力

### 4.1 平台工作台壳层

- 支持统一的 SaaS 工作台布局，包括轨道栏、主导航、顶部操作区和主内容区
- 支持首页、项目组合、项目作战室、OpenClaw 团队工作区、Agent 工作台、Agent 指挥页、系统运营、审计轨迹和设置等主模块
- 支持中文 / 英文双语切换
- 支持 Slack 风格的高密度信息分区和 AI Studio 风格的工作台骨架融合

### 4.2 项目协作与作战室

- 支持自然语言需求创建项目
- 支持理解确认卡、项目预解析、阶段状态查看、任务推进、人工介入、恢复推进、审批与驳回
- 支持以组合视图查看平台项目与 OpenClaw 工作区项目
- 支持在项目作战室中查看阶段、任务、交付物、时间线与实时输出流

### 4.3 OpenClaw 真实联动

- 支持读取真实 `~/.openclaw` 或自定义 `OPENCLAW_ROOT` 工作区
- 支持读取项目、Agent、任务、文档、最近会话与最近消息
- 支持查看项目报告与任务执行情况
- 支持对单个任务或批量任务进行状态回写
- 支持在平台中创建新的 OpenClaw Agent，并同步写入真实工作区配置

### 4.4 Agent 指挥与治理

- 支持单 Agent 指挥页进行模型切换、默认模型与回退模型设置
- 支持 `confirm_first` 与 `autonomous` 两种执行模式
- 支持先生成理解确认卡，再由用户确认执行
- 支持下发单 Agent 指令与批量 Agent 指令
- 支持修改 Agent 的介绍、职责、协作白名单、工具白名单、SOUL、SOP
- 支持长期记忆持久化、调用日志记录与每日 Token 使用摘要
- 支持设置单次输入、单次输出与每日 Token 上限

### 4.5 系统运营与监控

- 支持运行配置保存与连通性校验
- 支持健康检查、就绪度检查和审计日志查看
- 支持本地 Codex、Claude Code、OpenClaw 会话监控
- 支持通过 SSE 进行实时推送，而不是仅靠轮询刷新
- 支持按工具聚合 Token 与成本估算的成本治理面板

### 4.6 自动化验收与发布门禁

- 支持 `pnpm verify:smoke`
- 支持 `pnpm verify:closure`
- 支持 `pnpm test:acceptance`
- 已覆盖项目流、任务流、Agent 指挥流、运行配置流、OpenClaw 工作区流与任务回写流

## 5. 核心模块

- 总控首页：查看整体运行概览、关键项目、重点任务与系统状态
- 项目组合：统一查看应用内项目与 OpenClaw 项目
- 项目作战室：围绕单项目进行阶段推进、审批、任务和输出跟踪
- 团队工作区：展示真实 OpenClaw 团队当前项目、任务、文档与报告
- Agent 工作台：展示 Agent 画像、当前任务、记忆、负载和治理信息
- Agent 指挥页：完成模型切换、确认执行、任务下达、SOUL/SOP 编辑和记忆治理
- 系统运营：管理运行提供方、实时监控、成本治理、健康检查和就绪度
- 审计轨迹：查看关键配置、任务和指挥动作的审计记录

## 6. 典型使用流程

### 6.1 新建项目

1. 管理员登录平台。
2. 输入自然语言需求并生成理解确认卡。
3. 确认理解结果后创建项目。
4. 在项目作战室持续跟踪阶段、任务与交付物。

### 6.2 指挥单个 Agent

1. 进入 Agent 工作台并选择目标 Agent。
2. 调整模型、执行模式、Token 限额和治理策略。
3. 输入任务指令并生成理解确认卡。
4. 确认后执行，或在自主模式下持续推进。
5. 查看消息、记忆、用量与任务变化。

### 6.3 运营真实 OpenClaw 团队

1. 打开团队工作区查看真实项目与团队成员。
2. 跟踪项目状态、任务分布、阻塞项与项目报告。
3. 对任务进行更新、补充 Agent 配置或创建新 Agent。
4. 在系统运营页观察会话实时推送、成本面板与运行健康。

## 7. 当前部署形态

- 前端：React + Vite
- 后端：Express API
- 数据库：Prisma + SQLite
- 集成数据源：OpenClaw 本地工作区
- 运行提供方：`scripted`、`openai-compatible`
- 发布方式：本地部署、Docker 部署、GitHub Pages 主页展示、云主机 / Render 等正式环境部署

## 8. 当前版本边界

- 当前仍为单管理员模式，未实现多租户与细粒度 RBAC
- 数据库默认使用 SQLite，更适合单机或小规模部署
- 仍未正式接入 GitHub、Slack、飞书等外部业务系统的双向自动化
- 正式公网生产部署需要额外配置持久化卷、域名、HTTPS 与稳定运行环境

## 9. 验收结论

v1.0.1 已不是单纯展示型版本，而是一个能够连接真实 OpenClaw 工作区、具备 Agent 指挥与系统治理能力，并且已经通过关键闭环自动验证的可交付版本。它可以作为后续 1.x 系列持续迭代的稳定基础版本。
